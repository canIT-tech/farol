01 Terminar de codar e testar rafinha

Backlog de implementação (ver CLAUDE.md › "Próximos passos"). Ordem = dependência.

  • Passo 6 — Google Places + enrich. GooglePlacesProvider, PlacesModule, enrich no job do roteiro, swap_restaurant. Depende do Passo 4 (feito).
  • Passo 7 — Chat IA. ChatModule, loop de tool-calling, 9 tools → serviços, chat_messages. Depende de 4 + 5 + 6. Maior bloco de código restante.
  • Passo 8 — UI web + E2E. Telas do apps/web ligadas ao apps/api + fluxo Playwright completo. Depende do 7.
  • Pagamento no código novo — PaymentModule + webhook Stripe. Spec pronta: docs/negocio/2026-08-31-spec-pagamento.md (modelo de crédito, gate no roteiro, reembolso CDC). Depende do item 3.

Definition of Done de cada passo: cobertura 100% + unidade / integração / e2e / mutação verdes. PR que não bate os gates não entra.

04 Termos de uso + Política de privacidade felippe

Termos de uso

  • Escopo honesto (casa com a voz da marca): o Farol não reserva voo/hotel, não garante preço, o roteiro é sugestão — o usuário confere antes de comprar.
  • Conteúdo gerado por IA pode conter erros; responsabilidade do usuário na conferência.
  • Pagamento por viagem, regras de reembolso / estorno / cancelamento.
  • Propriedade do conteúdo do roteiro; lei e foro (Brasil).

Política de privacidade / LGPD

  • Já é necessária agora — a waitlist coleta e-mail.
  • Dados: e-mail, perfil de gosto, dados de viagem, pagamento (via Stripe).
  • Terceiros: Amadeus, Google Places, Anthropic, Stripe, provedor de e-mail, analytics.
  • Base legal, direitos do titular, opt-out, contato do encarregado. Consentimento explícito no formulário da waitlist + link para a política.

Cookies / consentimento opcional

  • Com Plausible (sem cookie): aviso mínimo. Com GA4 / Meta Pixel: banner de consentimento obrigatório.

06 Infra de produção rafinha · felippe (a definir) novo

  • Hosting: container para apps/api + apps/worker, deploy do apps/web (Next), Postgres gerenciado. Hospedagem agnóstica (container + Postgres + env).
  • Supabase de produção: projeto separado do dev (Auth + Postgres + Storage).
  • Rodar db:migrate (0000–0005) + db:seed (catálogo) no banco de produção.
  • Preencher todas as envs de produção (base em .env.example): DATABASE_URL, SUPABASE_*, ANTHROPIC_API_KEY, AMADEUS_*, JOBS_SCHEMA, *_DEEPLINK_TEMPLATE, NEXT_PUBLIC_API_URL, chaves da Stripe.
  • CI: fechar o débito A2 (envs novas no ci.yml) antes dos PRs de prod. DNS do domínio apontando para o hosting; HTTPS.
