**Goal:** Realizar as telas hi-fi (`*.dc.html`) em React no `apps/web`, consumindo a `apps/api` via `apiFetch`, usando os componentes de `packages/ui`. Fluxos: B2C padrão (onboarding → descoberta input → resultados → destino → roteiro → voo/hotel, com o trilho de chat) e B2C autônomo (entrada mínima → plano único). Fecha com um E2E Playwright ponta a ponta.

**Architecture:** App Router. Um `TripProvider` (client) carrega o `TripState` de `GET /trips/:id` e re-carrega após cada mutação (escolha de destino, chat, seleção de voo/hotel). O `AppShell` de `packages/ui` monta sidebar (resumo + `StepNav`) + miolo + trilho (`AdvisorChat`). O roteiro faz polling em `GET /trips/:id/itinerary` enquanto `status === "pending"`. O modo autônomo usa as mesmas telas de resultado, só que sem o passo de escolha (o back já devolve `chosenDestination`). Sessão via Supabase (Plano 2); rotas autenticadas atrás de `AuthGate`.

**Tech Stack:** herda dos Planos 1–2 e 9. Next.js 15, `@supabase/supabase-js`, `@playwright/test`, `@testing-library/react`.

**Spec:** `docs/superpowers/specs/2026-08-27-mvp-trip-design.md` §6 (fluxos), Apêndice (sequência). Telas: `Onboarding.dc.html`, `DiscoveryInput.dc.html`, `Main.dc.html`, `Itinerary.dc.html`, `FlightsHotels.dc.html`, `AutoInput.dc.html`, `AutoPlan.dc.html`. Design: `docs/design-system.md`.

## Global Constraints

- Herdam dos Planos 1–2 e 9 (pnpm, Node 22, cobertura 100% por pacote, mutação ≥ 90%, TDD, PT-BR, DoD = testes completos).
- **`apps/web` não tem lógica de negócio** — só orquestra chamadas e renderiza. Toda validação de entrada usa os schemas de `@farol/shared`.
- **Cobertura do `apps/web`:** `coverage.include` = `src/lib/**` + `src/hooks/**` + `src/components/**` (componentes com lógica). As páginas/rotas (`src/app/**`) são cobertas pelo **E2E Playwright**, não pelo Vitest — refletido no `include`.
- **Componentes de UI vêm de `packages/ui`.** O `apps/web` só compõe; não redefine tokens nem reimplementa `Button`/`Chip`/etc.
- **Estados obrigatórios em toda tela que busca dados:** carregando, vazio, erro (com retry), sucesso. Cada um coberto por teste.
- **Nada de fake status bar / teclado** em telas mobile (regra do `design`).
- **E2E** roda contra `apps/api` + `apps/worker` reais + Postgres de teste; Supabase trocado por um emissor de JWT de teste (mesmo util do Plano 2) e o `apiFetch` recebe esse token.
